# Typst Studio: what makes a UI look crafted, and six themes for it

Date: 2026-10-17. Status: research and proposals. Nothing in `src/` was changed. The interactive picker that goes with this is the "Studio Looks" artifact; its machine-readable twin is `themes.json` (same data as the token tables below).

## Findings first

1. **The "AI look" is a set of statistically common defaults, not one trick.** Models reproduce the most frequent patterns in their training code, so an open-ended prompt returns the average template: shadcn, Inter, a purple-to-blue gradient, rounded cards with soft grey shadows. [prg.sh](https://prg.sh/ramblings/Why-Your-AI-Keeps-Building-the-Same-Purple-Gradient-Website), [Kosta Canatselis](https://world.hey.com/kostac/spot-the-slop-a-ui-designer-s-guide-to-fixing-ai-defaults-4c448c9c).
2. **The purple has a traceable cause.** Adam Wathan publicly apologised in August 2025 for making every Tailwind UI button `bg-indigo-500`; the widespread copying of those demos taught models "modern = purple buttons" (as told by [prg.sh](https://prg.sh/ramblings/Why-Your-AI-Keeps-Building-the-Same-Purple-Gradient-Website); I could not open the original post).
3. **There is a measured list of tells.** Adrian Krebs scored 1,590 Show HN pages against about 16 to 18 patterns: Inter everywhere, "VibeCode Purple", permanent dark mode with mid-grey body text and all-caps section labels, gradients, coloured glows and box shadows, centred hero with a badge above the H1, coloured top or left card borders, identical icon-topped feature cards, emoji icons in a sidebar, shadcn, glassmorphism. 22% of pages hit four or more. ([Krebs](https://www.adriankrebs.ch/blog/design-slop/)). The author notes about 5 to 10% false positives.
4. **Fixing one tell just resets the clock.** Impeccable's tell list and Krebs both warn that swapping purple for cream-and-serif or Instrument Serif italic is the next default ([impeccable.style](https://www.impeccable.style/slop), [CodeMySpec](https://codemyspec.com/blog/vibe-coded-websites-look-the-same)). The durable fix is a choice with a reason: a real palette with named roles, a font that fits the product, per-element radius, one depth step.
5. **Pro tools get "crafted" from system, not decoration.** Linear defines a whole theme from three inputs (base, accent, contrast) in LCH so equal lightness looks equal, and deliberately limits how much blue leaks into neutrals ([Linear](https://linear.app/now/how-we-redesigned-the-linear-ui)). Geist and Radix assign each grey step one job (background, hover, border, text) and draw each border once ([Geist colours](https://vercel.com/geist/colors), [Radix scale](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)).

Caveat on sources: I did not find usable Reddit threads (r/webdev, r/UI_Design and similar) through search. Several blog and "skill" pages cite a Reddit analysis, but the figure could not be verified, so nothing here relies on it. The sources are designer blogs, a dataset write-up and product design notes.

## Principles worth copying

- **Neutral ramp with a hue bias, not zero-saturation grey.** Every surface step shares one faint hue (warm for Ember, cool for Nordic, blue-grey for Primer). Dead `0 0%` greys read as lifeless; tinted neutrals read as chosen. Linear keeps the bias small ("more neutral and timeless").
- **One accent, and it has a job.** Primary action, focus ring, selection, caret. Not folder tints, badges and borders all at once. One bold moment beats five subtle ones.
- **Each step of the scale has one job** (Geist, Radix): app background, subtle surface, hover, pressed, hairline border, strong border, solid, secondary text, primary text. The token set already follows this shape: `--background`, `--card`, `--popover`, `--secondary` / `--muted`, `--accent`, `--border`.
- **Border or shadow, never both on the same edge.** Impeccable lists "hairline border plus wide shadow" as defining one edge twice. Geist: draw a border once, keep shadows translucent. Dense tools use borders; a calm, airy tool can use floating panes with one soft shadow and no lines.
- **Elevation on dark comes from luminance, not shadow.** The app already does this in `.dark` (base, card, popover get lighter). Keep it.
- **Density is a decision.** Linear tightened sidebar, tabs and headers to cut noise. Pick a row height (26 to 32px) and keep every control on it.
- **Radius per element type, not one value everywhere.** CodeMySpec suggests smaller radius on fields and larger on cards. Uniform padding and radius is a named tell ("Break the uniformity on purpose", Canatselis). Here: `--radius-sm` for controls, `--radius` for panels, pill only for tiny status dots.
- **Type carries the personality.** Change the font before anything else (Canatselis). Avoid Inter by default. Use a monospace only where content is code or a path. Contrast a readable body size with a smaller label, but not all-caps everywhere.
- **Icons: one stroke weight, aligned with labels.** Lucide at 1.5 reads technical, 2 reads friendly. Pick it per theme and apply it everywhere, and align icon, label and button on one baseline (Linear calls this "felt more than seen").
- **Design the unhappy states.** Empty, loading and error states are where generated UIs look unfinished (Canatselis). Applies to the assets rail and the preview error state.
- **Contrast is a floor, not a mood.** The faintest grey in one popular Linear clone (about 3.6:1) fails AA for body text. All muted-foreground values in the themes below are at least 4.9:1 on their own background, checked by script.

## AI tells to avoid in this app

Checked against `src/` on 2026-10-17. The app is already clean on the loud ones: no gradients, no sparkle or bot icons, no emoji icons, no glass, no coloured left stripes (`grep` finds none).

| Tell | Where it shows up here | Suggested fix |
|---|---|---|
| Tiny all-caps tracked labels everywhere (named in Krebs' list) | 45 `uppercase` and 50 `text-[10px]` uses. Whole toolbar in `TypstView.tsx` (lines ~465 to 526: "TYPST", Code, Find, Assets, SVG, PDF at 10px uppercase tracking-wide) | Keep all-caps only for section labels (Images, Fonts). Use sentence-case 12 to 13px for buttons. |
| Untouched shadcn-style neutrals and one purple | `index.css` light and dark are zero-saturation greys; `--status-purple` / `--folder-purple` / `--folder-indigo` exist, and purple is the crop and screenshot tool colour (`FigureViewport.tsx`, `PlaceScreenshotDialog.tsx`) | A tinted neutral ramp per theme. Give the crop tool the theme accent or a status hue, not a lone purple. |
| Same radius and same menu recipe on everything | Context menus in `Sidebar.tsx` and `TypstView.tsx` all use `rounded-md border ... shadow-lg`: a border plus a large shadow on one edge | One depth step: popover border plus a small translucent shadow, or luminance only on dark. |
| Lifeless grey / mid-grey body | `--muted-foreground` `0 0% 65%` on dark `8%` is acceptable (about 7:1), but the chrome is pure neutral grey with a red primary token and no hue bias | One accent with one job, hue-biased neutrals. |
| Inter-like system sans, no opinion | `body` font stack is the system sans (`-apple-system`, `Segoe UI Variable`) | Choose a UI face and a code face per theme. |
| Missing states | Not audited in depth | Check assets rail empty state and compile error state when applying a theme. |

## Theme proposals

Six complete systems. Each maps 1:1 to the CSS variable names in `src/index.css` (dark and light, `--radius`, `--radius-sm`, `--radius-pill`, the `--status-*`, `--folder-*` and `--code-*` sets). Folder tints are derived from the theme's own status hues (teal from green, orange from amber, pink from purple, indigo from blue, slate a desaturated blue), so they stay in family. Applying a theme is a token swap plus the font, density and icon-stroke values listed per theme.

| Theme | Idea | Feels like |
|---|---|---|
| Ember | Warm charcoal, coral accent, hairlines, DIN type | Your Obsidian Minimal direction |
| Graphite | Near-black, thin blue, sharp, technical | Vercel / Linear |
| Mocha | Soft, rounded, pastel on blue-violet dark | Catppuccin, Arc |
| Dawn | Warm paper, floating panes, soft shadows | Things, Rose Pine Dawn |
| Nordic | Cool slate, frost blue, square-ish | Nord, IBM Carbon |
| Primer | Familiar blue-grey pro tool | GitHub, typst.app |

Palette provenance: Mocha, Dawn, Nordic and Primer use the published Catppuccin, Rose Pine, Nord and GitHub Primer values. Ember follows your Minimal reference (`#262626`, `#d1d1d1`, `#ff6c52`). Graphite approximates Geist (values from its documented scale roles, not copied token for token). Where a source colour failed 4.5:1 for muted text on light mode (Latte subtext, Dawn subtle), I darkened it, so those two are adjusted, not official. Dawn's green, and a few Ember and Graphite status hues, are not part of the source palettes and were chosen to match.

## Applying a theme later

1. Read the user's saved picks (`preset`, `mode`, `overrides`, `notes`) from the picker, and the matching entry in `themes.json`.
2. Replace the `:root` and `.dark` blocks in `src/index.css` with that theme's tokens. Apply `overrides.accentResolved` to `--primary` and `--ring` (and the matching `--primary-foreground`) if set.
3. Set `--radius`, `--radius-sm`, base font size (`body`), row heights and icon `strokeWidth` (lucide `strokeWidth` prop) from the theme or the overrides. `surface: shadows` means panes get a gap and a soft shadow instead of `border-r` and `border-b`.
4. Self-host the chosen fonts (all OFL except Bahnschrift, a Windows system font, which should keep `local()` with the fallback stack) and add them to the Docker image. Do not load from a font CDN.
5. Check the folder and status colours in the sidebar and the code colours in `code-theme.ts`, which currently retints only `--code-keyword` and `--code-accent`.
